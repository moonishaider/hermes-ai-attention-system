## Evidence levels

- **Live and acceptance-tested:** exercised against bounded real data with source/context and leakage checks.
- **Live but metadata-smoked:** authenticated inventory or metadata probes passed; real usefulness is not yet accepted.
- **Implemented locally, awaiting real acceptance:** code and deterministic tests pass; a supervised real test remains.
- **Shadow/preview only:** deliberately unable to perform the external action in normal Hermes runtime.
- **Externally blocked:** prepared but waiting on a provider, credential, permission, or official artifact.
- **Intentionally deferred:** excluded for safety or lack of demonstrated need.

## First-use defect correction — 6 August 2026

The reported absence-summary run was diagnosed from timing metadata without copying private results into Git. It performed seven model calls, two redundant channel-directory searches, one 103,875-character Slack search, and many broad channel reads; the prompt grew to about 59k input tokens and the useful turn took roughly two minutes. Provider read latency was not the primary problem. The corrected workflow resolves the exact context-local date first, starts with one concise time-bounded Slack search of at most 20 results, omits surrounding context, and reads only relevant threads afterward. This removes avoidable discovery and payload growth without replacing fresh evidence with stale cache or weakening citations.

The pre-change configuration/SOUL/USER state is preserved in an owner-only dated `~/.hermes/backups/prompt6-config-before-merge-*` directory, and the project database has a non-overwriting local backup under `backups/`. Neither backup is tracked or published.

## Voice final-answer correction — 6 August 2026

## Zoom MCP lifecycle correction — 7 August 2026

Zoom OAuth, scopes, token modes, endpoint, and tool discovery were healthy, but the provider's notification stream recycled before Hermes' default 180-second liveness proof. Five unproven reconnects therefore exhausted Hermes' rapid-drop budget, deregistering Zoom until the five-minute self-probe. A first configuration-only ping attempt confirmed that Zoom also recycles this provider session on the generic ping path. Hermes now supports a narrow per-server `keepalive_probe: list_tools` option, and the project installer applies that metadata-only probe every 15 seconds while explicitly disabling generic MCP resources/prompts. This preserves Hermes' generic anti-flapping protection and leaves only the four reviewed Zoom read operations registered. After a native Desktop restart, registration showed exactly four tools; the metadata probe remained healthy across the former rapid-drop interval, and a bounded real `search_meetings` call completed without a write or private meeting content in implementation output.
