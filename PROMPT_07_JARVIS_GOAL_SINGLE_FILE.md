## 1. Product outcome and architecture

Deliver one polished personal operating layer that feels like Syed's own Jarvis rather than stock Hermes or another chat window.

- agent reasoning and tools;
- sessions and conversation state;
- memory and learned skills;

The new frontend must not reimplement the agent.

### Fixed frontend decision

Build a packaged **Tauri 2 desktop application using React + TypeScript**, with a minimal Rust native layer, provisionally named `Jarvis.app`.

Use Tauri because it provides a normal macOS application, global shortcuts, menu-bar/background lifecycle, single-instance behavior, native notifications, secure local process management, and a flexible interface without the weight of Electron.

Implementation constraints:

- production static frontend assets only;
- no persistent Vite/React development server;
- do not use `tauri dev` if it starts a local development server;
- use component/unit tests, static frontend builds, Rust tests, and repeated packaged/debug app builds instead;
- no local LLM, Docker stack, Postgres/vector service, or second general-purpose daemon;
- subtle futuristic motion and HUD styling are welcome, but avoid GPU-heavy 3D effects, excessive animation, or visual noise on the 8 GB Mac;
- package, locally sign as appropriate for a private personal application, install to `/Applications/Jarvis.app`, and keep a reversible uninstall/rollback path.

### Hermes integration seam

Use supported Hermes programmatic interfaces first:

- OpenAI-compatible API server for agent turns;
- streaming output and tool-progress events;
- Hermes health/capability/model surfaces;
- run interruption endpoint;
- existing project plugin/backend endpoints for Attention, tasks, screen requests, provenance, actions, and project-specific state;
- gateway/session interfaces where needed.

Create one project-owned `HermesBackendAdapter` boundary so the UI is not coupled throughout the codebase to unstable Hermes internals.

The Tauri Rust layer should:

- start or attach to exactly one Hermes gateway/backend;
- health-check it;
- authenticate over loopback only;
- prevent duplicate processes;
- stream agent and tool events;
- interrupt an active run;
- expose only narrowly scoped native capabilities to React;
- stop owned processes on full Quit;
- never expose a broad arbitrary shell from the webview.

Store the local API secret in macOS Keychain when practical, otherwise in an owner-only file outside Git. Prefer Rust-side HTTP so browser CORS is unnecessary. Bind only to loopback.

If an essential feature is absent from Hermes's supported API, add the narrowest project plugin/adapter. Do not patch Hermes core unless no supported seam exists; any patch must be isolated, tested, documented, and reversible.

The stock Hermes Desktop app and existing launcher remain recovery/diagnostic fallbacks, not the normal product.

## 3. Reliable conversational voice

The current voice problems are mandatory defects to solve.

### Capture and turn handling

Jarvis must:

- capture from its own obvious microphone/push-to-talk UI;
- show live partial transcription;
- retain the audio buffer and final transcript locally until Hermes confirms receipt;
- never silently lose a dictated request;
- provide Retry/Edit/Discard if submission fails;
- prevent duplicate submission with an idempotency key;
- support tap-to-start/tap-to-end and hold-to-talk;
- tolerate natural pauses;
- never retain raw audio after successful acknowledgement unless Syed explicitly saves it.

Use the simplest reliable packaged-macOS approach. Prefer Web Audio/MediaRecorder in the Tauri webview if acceptance proves it reliable; use a narrow Rust audio implementation only when needed. Reuse the existing faster-whisper and Edge TTS assets rather than introducing unnecessary providers.

### Spoken versus displayed response

The backend response contract should support:

- `spoken_text`: natural, direct, conversational, normally one or two short sentences;
- `display_text`: complete answer, details, citations, uncertainty, and actions;
- `status`: what Jarvis is doing;
- route/context/source metadata.

Do not read markdown tables, citation URLs, long bullet lists, or full technical reports aloud. Keep the full information on screen.

Voice-originated turns may speak automatically. Typed turns should remain quiet unless Syed explicitly enables spoken typed replies. Make this contract deterministic rather than depending on a stale Hermes session toggle.

### True interruption

While Jarvis is speaking:

- pressing Stop must stop immediately;
- starting push-to-talk must stop speech and begin capture;
- spoken barge-in should stop output and accept the correction;
- the written answer remains visible;
- no fallback player may restart stopped audio;
- Cancel should interrupt the active Hermes run through the supported run-stop interface;
- all audio processes must end on full Quit.
