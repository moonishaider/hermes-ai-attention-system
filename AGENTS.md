## Product architecture rules

- One visible master assistant and initially one Hermes profile.
- Persistent specialists are durable modules/skills with instructions, scoped memory, allowed tools, templates, and tests. They wake on demand rather than running permanently.
- Complex work may spawn temporary isolated workers/reviewers while the specialist identity and memory persist.
- Immutable source provenance and flexible semantic labels coexist. Never replace source identity with an AI guess.
- Initial semantic contexts: `inside-success`, `mitchell`, `personal`, `mixed`, and `unknown`; new contexts are configuration/data, not code branches.
- Specialist and integration systems are registry/template driven so future modules and sources do not require a high-level rebuild.
- Prefer current Hermes-native capabilities and official MCP/native integrations. Custom services are fallbacks only when a secure supported route is unavailable.
- Start lightweight on an 8 GB Apple Silicon Mac: API models, lazy loading, bounded concurrency, SQLite/FTS/native state, no local frontier LLM, no permanent GPU inference, no unnecessary Docker stack, no permanent local Postgres, and no vector service until evaluation proves it is needed.
- A later CPU VPS may handle light 24/7 collection/scheduling; voice, screen, and direct computer/browser control remain local.
